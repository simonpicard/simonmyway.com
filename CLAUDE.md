# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- **Dev server:** `npm run dev`
- **Build:** `npm run build`
- **Lint (JS/TS):** `npm run lint`
- **Lint/type-check (Python):** `uv run ruff check scripts/`, `uv run ruff format --check scripts/`, `uv run ty check scripts/`
- **Python scripts:** `uv sync` then `uv run scripts/<script>.py` (Python 3.11). Dependencies live only in `pyproject.toml`/`uv.lock` — there is no `requirements.txt`.
- **Auto-enhance post photos (macOS):** `swift scripts/auto_enhance.swift <output-dir> <image>...` — Core Image's automatic adjustments, metadata kept. Run once on the original photos only (not charts or screenshots), into another directory, then copy the results into `public/img/posts/<post>/`.

There are no test suites in this project. CI runs on pushes to `master` and on PRs, only when the relevant files change: `.github/workflows/ci-web.yml` runs the JS lint and the Next.js build (sources, content, public/, web config), `.github/workflows/ci-python.yml` runs the ruff/ty checks (scripts/, Python config). The newsletter workflow installs deps with `uv`.

`content/videos.json` (YouTube cache) and `next-env.d.ts` (generated by Next.js, differs between dev and build) are git-ignored: never commit them.

## Architecture

This is a personal website (simonmyway.com) built with Next.js (App Router), TypeScript, and Tailwind CSS v4. Dark theme only.

### Internationalization

The site is bilingual (English + French). All pages live under `src/app/[locale]/` (`en` and `fr`); the root layout is `src/app/[locale]/layout.tsx`. Legacy unprefixed URLs (`/blog/:slug`, `/about`, ...) permanently redirect to `/en/...` via `next.config.js` — these redirects must never be removed. The root path `/` is special: `src/proxy.ts` negotiates the language (NEXT_LOCALE cookie set by the language switcher, then Accept-Language, defaulting to en) with a temporary 307 — never make it permanent, and never extend negotiation to deep URLs. UI strings live in `src/lib/i18n.ts` (`dictionaries`); hreflang alternates are emitted per page and in the sitemap.

### Content pipeline

- Blog posts are markdown files in `content/posts/en/` and `content/posts/fr/`, named `YYYY-MM-DD-title.md`. A translation shares its filename with the original — that filename is the key linking the two versions (hreflang, language switcher). A post missing from `fr/` simply doesn't appear on the French site.
- Frontmatter is parsed with gray-matter; titles are extracted from the first `# heading` if not in frontmatter. Slugs are derived from the localized title via `slugify()` (accents are transliterated), so French posts get French slugs. Never change `slugify()` in a way that alters existing slugs — URLs would break.
- Videos are fetched from the YouTube API and cached in `content/videos.json` with a 1-day TTL. Requires `YOUTUBE_CHANNEL_ID` and `YOUTUBE_API_KEY` env vars.
- RSS feeds are served at `/en/feed.xml` and `/fr/feed.xml` (Atom format) with full HTML content generated by markdown-it + highlight.js with inline CSS styles for email compatibility.

### Newsletter automation

A GitHub Actions workflow (`newsletter.yml`) is triggered manually (`workflow_dispatch` only, no schedule): Simon runs it himself once a post is live and reviewed — never trigger it on his behalf. Each run sends every post of the day, so it must run once per publication.
1. `scripts/check_feed.py` — fetches both live RSS feeds (en + fr), finds entries published today in Brussels time (or on the optional `date` input / `NEWSLETTER_DATE`, `YYYY-MM-DD`), outputs them as JSON tagged with their language
2. `scripts/send_newsletter.py` — creates and sends Mailchimp campaigns for each new entry, targeted by language: subscribers with the `LANGUAGE` merge field set to `fr` get French campaigns, everyone else gets English ones (merge tag configurable via `MAILCHIMP_LANGUAGE_MERGE_TAG`)

### Key lib modules

- `src/lib/posts.ts` — reads/parses markdown posts from disk, provides `getAllPosts(locale)`, `getPostBySlug(locale, slug)`, `getTranslation()` and `getBlogPathMap()`
- `src/lib/i18n.ts` — locale list and UI-string dictionaries
- `src/lib/markdown.ts` — server-side markdown-to-HTML conversion (used for RSS feed content); converts highlight.js classes to inline styles
- `src/lib/videos.ts` — YouTube API fetching with file-based caching

### Rendering

Blog posts render client-side using `react-markdown` + `remark-gfm` + PrismJS for syntax highlighting (see `blog/[slug]/page.tsx`). The RSS feed uses a separate server-side rendering path via markdown-it + highlight.js (`src/lib/markdown.ts`).

Portrait images are detected from their real size (width/height ≤ 0.8, read with `sharp` in `src/lib/images.ts`), with no markup in the markdown. On wide screens, `src/lib/remark-portrait-photos.ts` shows them as tall as a full-width 3:2 photo, floated alternately right and left (photos shown alone don't count), and moves them up within their section (never past a heading or another image) so the surrounding text fills the space beside them; if the section is too short, the photo is shown alone, centered (CSS in `globals.css`). On phones, photos are full width and appear where they are written in the markdown: a photo moved up is wrapped with the blocks it passed (`post-portrait-group`), and the CSS shows it back after them. So in the markdown, place a portrait photo after at least one paragraph of its section. Posts are pre-rendered at build (`generateStaticParams`), when the images are on disk to be measured. The RSS feed is not affected.

### Path alias

`@/*` maps to `./src/*` (configured in tsconfig.json).

## Analytics

Plausible is loaded by hand in `src/app/[locale]/layout.tsx` (no `next-plausible`), served same-origin under `/e/...` and proxied by the rewrites in `next.config.js`: keep the paths in sync. Self-hosted Umami (`tiger.ourway.be`) is loaded alongside, for pageviews, heatmaps and session replay.
